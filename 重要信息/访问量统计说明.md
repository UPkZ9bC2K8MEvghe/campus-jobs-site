# 访问量统计说明（独立访客）

## 计数规则
- **同一台电脑 + 同一个 IP 只计 1 次**，永久去重（不是每次刷新都 +1）。
- 「台电脑」用浏览器本地生成的设备 ID（localStorage `campus-jobs-device-id`）识别。
- 服务端只存 `SHA-256(盐 + IP + 设备ID)`，不保存原始 IP。
- 顶部显示：总访客数 + 今日新增（按北京时间）。

注意：
- 同一台电脑换了网络（IP 变化）会再计 1 次；同一网络下的不同电脑各计 1 次。
- 清除浏览器数据、换浏览器、无痕模式会被视为新设备。
- GitHub Pages 镜像站和本地 `npm run preview` 没有后端，计数器自动隐藏，不报错。

## 文件
- `functions/api/visit.js`：Cloudflare Pages Function（POST 计数，GET 只读）
- `assets/app.js`：`deviceId()`、`trackVisit()`，页面加载完 1.5 秒后上报
- `index.html` / `assets/styles.css`：顶部 `#visitCounter`
- `sw.js`：`/api/` 不走缓存；`_headers`：`/api/*` no-store

## 一次性配置（必须做，否则计数器不显示）
1. Cloudflare 后台 → **Workers & Pages → D1** → 创建数据库，名字随意，例如 `campus-jobs-visits`。
   （表会在第一次请求时自动创建，不需要手动建表。）
2. 打开 Pages 项目 `campus-jobs` → **Settings → Bindings（或 Functions → D1 database bindings）** → 添加：
   - 变量名：`VISITS_DB`
   - 数据库：上一步创建的库
   - Production 和 Preview 都要加。
3. （可选）**Settings → Variables** 添加 `VISIT_SALT`，填一串随机字符，用于哈希加盐。
4. 重新部署一次。`wrangler pages deploy dist` 会自动带上项目根目录下的 `functions/`，
   因此部署命令**必须在项目根目录执行**（现有 GitHub Actions 已满足）。

## 验证
- 打开 `https://campus-jobs.pages.dev/api/visit`，应返回 `{"total":…, "today":…}`。
- 返回 `VISITS_DB 未绑定` 说明第 2 步没生效。

## 查数据 / 清零
在 D1 控制台执行：
```sql
SELECT COUNT(*) FROM visitors;                         -- 总访客
SELECT day, COUNT(*) FROM visitors GROUP BY day ORDER BY day DESC LIMIT 30;  -- 每日新增
DELETE FROM visitors;                                  -- 清零
```

## 额度
D1 免费版：每天 500 万次读、10 万次写、5GB 存储。每个新访客写 1 次，足够用。
